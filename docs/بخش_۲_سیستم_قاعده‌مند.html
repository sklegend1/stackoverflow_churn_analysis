🎯 هدف این بخش

در این بخش یک سیستم قاعده‌مند و تفسیری می‌سازیم که بتواند برای هر کاربر بگوید آیا در معرض Churn است یا خیر. این سیستم باید:

  • ✅ قابل توضیح باشد (Interpretable)
  • ✅ پارامترهای قابل تنظیم داشته باشد
  • ✅ مبنایی برای مقایسه با مدل‌های پیچیده‌تر باشد

۱. فرمول قاعده‌مند

۱.۱ قاعده‌ی اصلی

برای کاربر u در پرسونا p:

Churn(u) = 𝟙[ WA(u, Tp) < Ap ]
پارامتر تعریف نحوه‌ی محاسبه
Tp پنجره‌ی زمانی مشاهده α × p95(gap بین اکشن‌های کلیدی)
Ap آستانه‌ی فعالیت از منحنی Precision-Recall
WA فعالیت وزن‌دار Σ gain برای اکشن‌های کلیدی

۱.۲ چرا Gain به‌جای Count؟

انتخاب بین دو رویکرد

رویکرد Count-based Gain-based ✅
فرمول Σ count(event) Σ gain(event)
مزیت ساده وزن‌دهی هوشمند
معایب همه‌ی اکشن‌ها برابر وابسته به XGBoost

نتیجه: اکشن‌های مختلف اهمیت متفاوتی دارند. یک پاسخ (Answer) ارزشمندتر از یک نظر (Comment) است. Gain از XGBoost این تمایز را به‌صورت داده‌محور یاد می‌گیرد.

۲. استخراج Core Activities

۲.۱ چرا Core Activities؟

تمام انواع Action برای تشخیص Churn اهمیت یکسان ندارند. برخی فعالیت‌ها:

  • ❌ بسیار نادر هستند
  • ❌ برای برخی پرسوناها اصلاً انجام نمی‌شوند
  • ❌ نویز ایجاد می‌کنند

۲.۲ رویکرد: XGBoost One-vs-Rest

برای هر پرسونا، یک مدل XGBoost آموزش می‌بینیم که:

Targetp = { 1 if persona = p
0 otherwise }

مراحل استخراج Core Activities:

  1. برای هر پرسونا، یک classifier One-vs-Rest بساز
  2. از Feature Importance (Gain) استفاده کن
  3. ۷ اکشن با بیشترین Gain را انتخاب کن
  4. فقط این اکشن‌ها را در Event Log نگه دار (Core Event Log)
for persona in range(20): # تعریف target به‌صورت One-vs-Rest df = fm.with_columns([ (pl.col("persona") == persona).cast(pl.Int8).alias("target") ]) X = df.select(feature_cols).to_pandas() y = df.select("target").to_pandas()["target"] # آموزش XGBoost dtrain = xgb.DMatrix(X, label=y) params = { "objective": "binary:logistic", "max_depth": 6, "learning_rate": 0.1, } model = xgb.train(params, dtrain, num_boost_round=200) # استخراج Gain importance = model.get_score(importance_type="gain")

۲.۳ چرا ۷ اکشن؟

این عدد بر اساس آزمایش تجربی انتخاب شده است:

  • تعداد کمتر → از دست رفتن اطلاعات
  • تعداد بیشتر → اضافه شدن نویز
  • ۷ اکشن → تعادل خوب بین اطلاعات و نویز

۳. تخمین Tp و Ap

۳.۱ تخمین Tp: پنجره‌ی زمانی

Tp باید بر اساس ریتم طبیعی هر پرسونا باشد:

Tp = α × p95(gap بین اکشن‌های کلیدی)

که در آن:

  • p95(gap) = صدک ۹۵ فاصله‌ی زمانی بین اکشن‌های کلیدی پرسونا
  • α = ضریب مقیاس‌بندی (با Grid Search پیدا می‌شود)
# محاسبه‌ی p95 برای هر پرسونا gap_stats = ( core_eventlog .filter(pl.col("gap_time_key_actions_seconds") > 0) .group_by("persona") .agg( pl.col("gap_time_key_actions_seconds") .quantile(0.95) .alias("p95_gap") ) ) # Grid Search روی alpha alpha_values = np.arange(3, 10, 1) # [3, 4, 5, ..., 9] for alpha in alpha_values: Tp = alpha * p95_gap # ارزیابی با این Tp...
⚠️ محدودیت مهم: هر Tp که خارج از بازه‌ی ۶۰–۲۷۰ روز باشد، نادیده گرفته می‌شود. این Sanity Check از پارامترهای نامعقول جلوگیری می‌کند.

۳.۲ تخمین Ap: آستانه‌ی فعالیت

دو روش برای تخمین Ap:

روش ۱: XGBoost + Precision-Recall Curve

  1. برای هر پرسونا، WA را به‌عنوان feature محاسبه کن
  2. یک XGBoost Classifier آموزش بده (target = actual churn)
  3. منحنی Precision-Recall را رسم کن
  4. آستانه‌ای را انتخاب کن که F1 را بیشینه می‌کند
# آموزش XGBoost model = XGBClassifier(max_depth=6, learning_rate=0.1) model.fit(X, y) # محاسبه‌ی احتمالات probs = model.predict_proba(X)[:, 1] # Precision-Recall Curve precisions, recalls, thresholds = precision_recall_curve(y, probs) # پیدا کردن بهترین threshold f1_scores = 2 * (precisions * recalls) / (precisions + recalls + 1e-9) best_idx = np.argmax(f1_scores) Ap = thresholds[best_idx]

۴. ارزیابی سیستم

۴.۱ تعریف Actual Churn

برای ارزیابی، باید بدانیم کاربر واقعاً Churn شده یا نه:

actual_churn = 1 if کاربر هیچ رویدادی
در [cutoff + grace, cutoff + grace + 365روز]
نداشته باشد

چرا Grace Period؟

دوره‌ی مهلت (Grace Period) از برچسب‌گذاری اشتباه جلوگیری می‌کند:

  • کاربر ممکن است موقتاً مشغول باشد (تعطیلات، کار فشرده)
  • با grace period، فقط ناپدید شدن‌های طولانی‌مدت را Churn می‌دانیم
  • در این پروژه: grace_days = 90-180 روز
Timeline: |<---- Tp ---->|<-- Grace -->|<---- Observation (365d) ---->| | | | | window_start cutoff cutoff+grace cutoff+grace+365d اگر کاربر در بازه‌ی Observation هیچ فعالیتی نداشت → Churn = 1

۴.۲ روش Sliding Window

به‌جای ارزیابی روی یک تاریخ، روی پنجره‌های متعدد ارزیابی می‌کنیم:

def generate_windows(start_year=2015, end_year=2023, step_months=6): windows = [] year = start_year month = 1 while year < end_year: cutoff = datetime(year, month, 1) windows.append(cutoff) month += step_months if month > 12: month -= 12 year += 1 return windows # خروجی: 24 پنجره از 2012 تا 2024 windows = generate_windows(2012, 2024, 6)
چرا Sliding Window؟
  • ✅ پایداری مدل را در طول زمان می‌سنجد
  • ✅ از overfitting به یک تاریخ خاص جلوگیری می‌کند
  • ✅ Temporal Drift را آشکار می‌کند

۴.۳ معیارهای ارزیابی

معیار فرمول تفسیر
Precision TP / (TP + FP) از کسانی که گفتیم Churn می‌شوند، چند نفر واقعاً Churn شدند؟
Recall TP / (TP + FN) از کسانی که واقعاً Churn شدند، چند نفر را تشخیص دادیم؟
F1 2 × (P × R) / (P + R) میانگین هارمونیک Precision و Recall
Rate Ratio pred_rate / actual_rate نسبت نرخ پیش‌بینی‌شده به واقعی (باید ~1 باشد)
