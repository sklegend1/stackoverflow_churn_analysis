۱. تعریف مسئله: Churn چیست؟

۱.۱ چالش اصلی

Stack Overflow بزرگ‌ترین پلتفرم پرسش و پاسخ برنامه‌نویسی جهان است. در این پلتفرم، محتوای با کیفیت توسط کاربران خبره تولید می‌شود. یک پاسخ‌دهنده‌ی باتجربه که سال‌ها در حوزه‌ی خاصی فعالیت کرده، ارزشی غیرقابل جایگزین دارد.

از دست دادن چنین کاربرانی ضربه‌ای جدی به کیفیت پلتفرم وارد می‌کند. بنابراین پیش‌بینی اینکه کدام کاربران در آستانه‌ی ترک پلتفرم هستند اهمیت استراتژیک دارد.

۱.۲ رویکرد رفتاری

چرا نمی‌توانیم به «حذف حساب» اکتفا کنیم؟

در بسیاری از پروژه‌های Churn، ریزش بر اساس وضعیت حساب تعریف می‌شود: آیا کاربر اکانتش را حذف کرده؟ آیا اشتراکش را لغو کرده؟

اما در Stack Overflow چنین تعریفی کارساز نیست. کاربران معمولاً اکانتشان را حذف نمی‌کنند — فقط دیگر برنمی‌گردند.

بنابراین در این پروژه، Churn به‌صورت رفتاری (Behavioral) تعریف شده است:

کاربر زمانی در معرض Churn قرار دارد که
سطح فعالیت مؤثر او در یک پنجره‌ی زمانی مشخص،
از یک آستانه‌ی حداقلی کمتر شود

۱.۳ فرمول پایه

برای کاربر u در پرسونا (گروه رفتاری) p:

WA(u, Tp) < Ap ⟹ Churn Signal
پارامتر تعریف واحد
Tp پنجره‌ی زمانی مشاهده (Time Period) ثانیه / روز
Ap آستانه‌ی فعالیت مؤثر (Activity Threshold) بدون واحد (وزن تجمیعی)
WA فعالیت وزن‌دار (Weighted Activity) مجموع وزن‌دار اکشن‌ها

۱.۴ چرا پرسونا-محور؟

کاربران Stack Overflow رفتارهای بسیار متفاوتی دارند. اگر برای همه یک Tp و Ap ثابت تعریف کنیم، با مشکل مواجه می‌شویم:

نوع کاربر الگوی فعالیت مثال
پاسخ‌دهنده‌ی حرفه‌ای هر روز ۳-۵ پاسخ Jon Skeet
پرسش‌کننده‌ی گاه‌به‌گاه هر ۲ ماه یک سؤال دانشجوی ترم‌محور
ویراستار ویرایش محتوای دیگران Curator
ناظر رأی‌دهی و نظارت Moderator

۲. معماری داده: از MySQL تا Event Log

۲.۱ انتخاب ابزار

با توجه به حجم بالای داده‌ها (چندین میلیون رکورد) و محدودیت منابع، استفاده از Apache Spark سنگین به نظر می‌رسید. بنابراین ترکیب زیر انتخاب شد:

ابزار نقش مزیت
MySQL ذخیره‌سازی اولیه دیتاست رسمی Stack Overflow
DuckDB کوئری‌های SQL روی فایل Lazy، بدون Memory overhead
Polars پردازش DataFrame Rust-based، بسیار سریع
Parquet فرمت ذخیره‌سازی Columnar، فشرده، قابل Lazy scan

۳. Event Log: قلب سیستم

۳.۱ تعریف Event Log

Event Log یک ساختار داده‌ای است که تمام رویدادهای مرتبط با کاربران را به‌صورت زمانی مرتب شده نگه می‌دارد:

ستون نوع توضیح
user_id Int64 شناسه‌ی کاربر
timestamp Datetime زمان وقوع رویداد
action_type_id Int32 نوع اکشن (کدگذاری شده)
persona Int32 شماره‌ی پرسونا (0–19)
gap_time_actions_seconds Float64 فاصله از اکشن قبلی (ثانیه)
gap_time_actions_days Float64 فاصله از اکشن قبلی (روز)

۳.۲ سه منبع رویداد

منبع ۱: ایجاد پست (Posts)

# CREATE_QUESTION = 1 # CREATE_ANSWER = 2 events_create_post = ( posts .join(users, left_on="owneruserid", right_on="user_id") .with_columns([ pl.when(pl.col("posttypeid") == 1) .then(pl.lit(1)) # Question .when(pl.col("posttypeid") == 2) .then(pl.lit(2)) # Answer .alias("action_type_id"), ]) )

منبع ۲: تاریخچه‌ی پست (PostHistory)

جدول posthistory شامل تمام تغییرات روی پست‌هاست. هر PostHistoryTypeId به یک action_type_id داخلی نگاشت می‌شود:

PostHistoryTypeId action_type_id نام
4 13 Edit Title
5 14 Edit Body
6 15 Edit Tags
10 30 Close Post
11 31 Reopen Post
⚠️ نکته مهم: فقط رویدادهایی که UserId آنها در لیست کاربران هدف (filtered_users) است، وارد Event Log می‌شوند.

منبع ۳: نظرات (Comments)

# COMMENT_ACTION = 70 events_comments = ( comments .join(users, left_on="userid", right_on="user_id") .with_columns([ pl.lit(70).alias("action_type_id"), ]) )

۳.۳ محاسبه‌ی Gap Time

یکی از مهم‌ترین ویژگی‌های Event Log، فاصله‌ی زمانی بین رویدادهای متوالی هر کاربر است:

# مرتب‌سازی بر اساس کاربر و زمان eventlog_lazy = eventlog_lazy.sort(["user_id", "timestamp"]) # محاسبه‌ی Gap Time eventlog_lazy = eventlog_lazy.with_columns([ # Gap Time به ثانیه (pl.col("timestamp") .diff() .over("user_id") / 1_000_000) .alias("gap_time_actions_seconds"), # Gap Time به روز (pl.col("timestamp") .diff() .over("user_id") / (1_000_000 * 60 * 60 * 24)) .alias("gap_time_actions_days"), ])

۳.۴ چرا Votes حذف شد؟

تصمیم مهم: حذف جدول Votes

رأی‌هایی که یک پست دریافت می‌کند (Upvote / Downvote) نشانه‌ی فعالیت کاربر نیست. این رویدادها در واقع ری‌اکشن به محتوای کاربر هستند، نه رفتار خود کاربر.

مخصوصاً اینکه بسیاری از انواع vote اصلاً UserId ندارند — یعنی مشخص نمی‌شود چه کسی آن رفتار را انجام داده.

نتیجه: Votes به‌عنوان "event کاربر" وارد sequence نشد.
