## ۶.۱ مقدمه

### ۶.۱.۱ خلاصه‌ی سفر پنج فصل

در این پروژه، سیستم پیش‌بینی Churn کاربران Stack Overflow را در سه سطح پیچیدگی طراحی و پیاده‌سازی کردیم:

| فصل | رویکرد | ایده‌ی اصلی | پارامترهای قابل‌تنظیم |
|-----|--------|------------|---------------------|
| ۳ | **Rule-based** | $WA(T_p) < A_p$ | $T_p$, $A_p$ per-persona |
| ۴ | **Enhanced WA** | WA_simple, WA_trend, WA_recency, WA_enhanced | $T_p$, $A_p$, نوع WA |
| ۵ | **LSTM Multi-Task** | یادگیری توالی رویدادها + پیش‌بینی Ap/Tp | Sequence=50, Hidden=128, Layers=2 |

### ۶.۱.۲ سؤالات این فصل

1. **کدام رویکرد در کدام شرایط بهتر است؟**
2. **آیا LSTM همیشه برنده است؟**
3. **Trade-off بین دقت و تفسیرپذیری چیست؟**
4. **توصیه‌ی نهایی برای Production چیست؟**

## ۶.۶ Trade-off و توصیه‌های کاربردی

### ۶.۶.۱ دقت vs. تفسیرپذیری

```
تفسیرپذیری
    ▲
    │
 5  │  ★ Rule-based (F1=0.50)
    │
 4  │      ★ Enhanced WA (F1=0.62)
    │
 3  │
    │
 2  │                      ★ LSTM (F1=0.79)
    │
 1  ┼──────┬──────┬──────┬──────┬──────►
        0.50   0.60   0.70   0.80   0.90  دقت (F1)
```

### ۶.۶.۲ انتخاب رویکرد بر اساس سناریو

| سناریو | رویکرد پیشنهادی | دلیل |
|--------|-----------------|------|
| **استارتاپ / MVP** | Enhanced WA | سریع، قابل‌تفسیر، کافی |
| **Real-time API** | Rule-based | سرعت < 50ms |
| **Batch Processing شبانه** | LSTM | دقت اولویت دارد |
| **گزارش به مدیریت** | Enhanced WA | توضیح‌پذیر |
| **سیستم Enterprise** | LSTM + Rule-based | دقت + توضیح |

### ۶.۶.۳ انتخاب بر اساس حجم داده

| حجم کاربران | رویکرد | دلیل |
|-------------|--------|------|
| < 10,000 | Rule-based | LSTM Overfit می‌شود |
| 10,000 – 100,000 | Enhanced WA | توازن خوب |
| > 100,000 | LSTM | استفاده از پتانسیل داده |

**Stack Overflow:** ~5 میلیون کاربر فعال → LSTM توجیه‌پذیر است.

## ۶.۷ معماری پیشنهادی ترکیبی

### ۶.۷.۱ ایده

بهترین استراتژی: **استفاده از هر سه رویکرد**

```
┌─────────────────────────────────────────────────────────────┐
│                    Hybrid Churn System                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐    │
│  │  Rule-based  │   │ Enhanced WA  │   │    LSTM      │    │
│  │   WA < Ap    │   │  + Recency   │   │  Multi-Task  │    │
│  └──────┬───────┘   └──────┬───────┘   └──────┬───────┘    │
│         │                  │                  │             │
│         └──────────────────┼──────────────────┘             │
│                            ▼                                │
│                   ┌────────────────┐                        │
│                   │   Ensemble     │                        │
│                   │   + Explainer  │                        │
│                   └────────┬───────┘                        │
│                            ▼                                │
│                   ┌────────────────┐                        │
│                   │    Output:     │                        │
│                   │  P(Churn)=0.87 │                        │
│                   │  Reasons: ...  │                        │
│                   └────────────────┘                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### ۶.۷.۲ کد ترکیب ساده

```python
def hybrid_predict(user_id, eventlog, cutoff, models):
    """
    پیش‌بینی ترکیبی با توضیحات
    """
    # 1. Rule-based
    wa = compute_wa(eventlog, user_id, cutoff, models['Tp'])
    p_rule = 1.0 if wa < models['Ap'] else 0.0
    
    # 2. Enhanced WA
    wa_recency = compute_wa_recency(eventlog, user_id, cutoff)
    p_enhanced = 1.0 if wa_recency < models['Ap_recency'] else 0.0
    
    # 3. LSTM
    sequence = create_sequence(eventlog, user_id, cutoff)
    with torch.no_grad():
        p_lstm, ap_pred, tp_pred = models['lstm'](sequence)
    
    # 4. Ensemble (weighted)
    p_final = 0.2 * p_rule + 0.3 * p_enhanced + 0.5 * p_lstm
    
    # 5. Generate explanation
    explanation = []
    if wa < models['Ap']:
        explanation.append(f"فعالیت کم: WA={wa:.2f} < {models['Ap']:.2f}")
    if wa_recency < models['Ap_recency']:
        explanation.append(f"عدم فعالیت اخیر: Recency کم")
    if p_lstm > 0.5:
        explanation.append(f"مدل LSTM: {p_lstm:.0%} احتمال Churn")
    
    return {
        'probability': p_final,
        'prediction': 'Churn' if p_final > 0.5 else 'Active',
        'explanation': ' | '.join(explanation),
        'components': {
            'rule': p_rule,
            'enhanced': p_enhanced, 
            'lstm': p_lstm
        }
    }
```

## ۶.۸ محدودیت‌های پروژه

### ۶.۸.۱ محدودیت‌های داده

| محدودیت | تأثیر | راه‌حل آینده |
|---------|-------|-------------|
| فقط Stack Overflow | عدم تعمیم‌پذیری | تست روی پلتفرم‌های دیگر |
| داده‌ی ۲۰۰۸-۲۰۲۴ | تغییرات رفتاری | Continual Learning |
| Vote حذف شده | از دست دادن سیگنال | تحلیل VoteType جداگانه |
| فقط کاربران ≥10 رویداد | Bias | شامل کردن Lurkers |

### ۶.۸.۲ محدودیت‌های مدل

| محدودیت | توضیح |
|---------|-------|
| Grace Period ثابت (90 روز) | ممکن است per-persona بهتر باشد |
| Churn Binary | گرادیان خطر (Low/Medium/High) مفیدتر است |
| Persona ثابت | کاربران می‌توانند تغییر پرسونا دهند |
| فقط Offline Evaluation | A/B Test در Production لازم است |

### ۶.۸.۳ Temporal Drift

یافته‌ی فصل ۴: **Drift وجود دارد اما تنظیم سالانه بهبود چندانی نمی‌دهد.**

احتمالاً دلیل: LSTM الگوهای زمانی را خودش یاد می‌گیرد (با ویژگی‌های `era`, `month`, `year`).

## ۶.۱۰ درس‌های آموخته‌شده

### ۶.۱۰.۱ درس‌های فنی

1. **ساده شروع کن:** Rule-based قبل از Deep Learning
2. **داده‌ی خوب > مدل پیچیده:** ویژگی‌های ساده کافی‌اند
3. **Temporal Split اجباری:** هرگز Random Split در Time Series
4. **Per-Persona Parameters:** یک مدل برای همه کار نمی‌کند
5. **ویژگی‌های روان‌شناختی بی‌فایده:** در این مسئله کمکی نکردند
6. **Recency مهم‌تر از Total Activity:** WA_recency در اکثر پرسوناها برد

### ۶.۱۰.۲ درس‌های عملی

1. **مستندسازی از اول:** این ۶ فصل باید از ابتدا نوشته می‌شد
2. **Version Control همه‌چیز:** کد + داده + مدل
3. **Reproducibility:** `SEED = 42` همه‌جا
4. **Multiple Metrics:** F1, Precision, Recall, AUC همه مهم‌اند
5. **Ablation Studies:** مقایسه‌ی ویژگی‌ها ضروری است
