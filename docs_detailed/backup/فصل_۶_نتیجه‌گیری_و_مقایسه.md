## ۶.۱ مقدمه

### ۶.۱.۱ خلاصه‌ی سفر

در این پروژه، یک سؤال ساده داشتیم: **«آیا می‌توان پیش‌بینی کرد که کدام کاربران Stack Overflow را ترک خواهند کرد؟»**

برای پاسخ، سه رویکرد با پیچیدگی‌های مختلف امتحان کردیم:

| فصل | رویکرد | ایده‌ی اصلی | پیچیدگی | عملکرد (F1) |
|-----|--------|------------|---------|-------------|
| ۳ | **Rule-based** | اگر فعالیت کم → Churn | ⭐ کم | 0.35–0.58 |
| ۴ | **Enhanced WA** | فعالیت + روند + تازگی | ⭐⭐ متوسط | 0.52–0.67 |
| ۵ | **LSTM** | یادگیری خودکار الگوها | ⭐⭐⭐ زیاد | 0.60–0.90 |

**نتیجه‌ی کلی:** هرچه مدل پیچیده‌تر، دقت بالاتر — اما trade-off‌هایی وجود دارد.

### ۶.۱.۲ سؤالات کلیدی این فصل

۱. **کدام رویکرد بهتر است؟** → بستگی به شرایط دارد!
۲. **آیا LSTM همیشه بهتر است؟** → نه، گاهی Rule-based کافی است
۳. **چه زمانی از کدام استفاده کنیم؟** → تحلیل می‌کنیم
۴. **آیا می‌توان ترکیبشان کرد؟** → بله، Ensemble!

## ۶.۵ پیشنهاد سیستم ترکیبی (Ensemble)

### ۶.۵.۱ معماری پیشنهادی

**سیستم Ensemble:**

| مرحله | مدل | ورودی | خروجی |
|-------|------|-------|--------|
| ۱ | Rule-based | WA, Ap | پیش‌بینی 0/1 |
| ۲ | Enhanced WA | WA_recency | پیش‌بینی 0/1 |
| ۳ | LSTM | Sequence | P(Churn) |
| ۴ | Meta-Classifier | سه پیش‌بینی | P(Churn) نهایی + Explanation |

**روش ترکیب:** Weighted Voting / Stacking

### ۶.۵.۲ Weighted Voting

$$
P_{\text{final}}(\text{Churn}) = w_1 \cdot P_{\text{Rule}} + w_2 \cdot P_{\text{WA}} + w_3 \cdot P_{\text{LSTM}}
$$

با وزن‌های یادگرفته‌شده:

```python
def weighted_ensemble(p_rule, p_wa, p_lstm, weights=(0.2, 0.3, 0.5)):
    """
    ترکیب وزن‌دار سه مدل
    """
    w1, w2, w3 = weights
    p_final = w1 * p_rule + w2 * p_wa + w3 * p_lstm
    return p_final

# تعیین وزن‌ها با Cross-validation
from sklearn.linear_model import LogisticRegression

def learn_weights(p_rules, p_was, p_lstms, y_true):
    """
    یادگیری وزن‌های بهینه
    """
    X = np.column_stack([p_rules, p_was, p_lstms])
    model = LogisticRegression()
    model.fit(X, y_true)
    
    # وزن‌ها از coefficients
    weights = model.coef_[0]
    weights = weights / weights.sum()  # نرمال‌سازی
    
    return weights
```

```python
def generate_explanation(user_id, predictions, features):
    """
    تولید توضیح برای پیش‌بینی
    """
    exp = f"User #{user_id}: {predictions['final']} ({predictions['confidence']:.0%})\n\n"
    
    exp += "📊 دلایل:\n"
    
    # Rule-based reason
    if predictions['rule_based'] == 'Churn':
        exp += f"  1. فعالیت وزن‌دار (WA={features['wa']:.2f}) کمتر از آستانه ({features['ap']:.2f})\n"
    
    # Trend reason
    if features['wa_trend'] < 0:
        exp += f"  2. روند فعالیت کاهشی (slope={features['wa_trend']:.3f})\n"
    
    # Recency reason
    if features['days_since_last'] > 30:
        exp += f"  3. آخرین فعالیت: {features['days_since_last']:.0f} روز پیش\n"
    
    # LSTM top attention
    exp += f"  4. مهم‌ترین رویداد اخیر: {features['top_attention_event']}\n"
    
    exp += "\n💡 پیشنهاد:\n"
    if predictions['final'] == 'Churn':
        exp += "  - ارسال ایمیل بازگشت با پیشنهاد ویژه\n"
        exp += "  - دعوت به رویداد آنلاین\n"
    
    return exp
```

**مثال خروجی:**

```
User #12345: Churn (87% confidence)

📊 دلایل:
  1. فعالیت وزن‌دار (WA=0.12) کمتر از آستانه (0.35)
  2. روند فعالیت کاهشی (slope=-0.045)
  3. آخرین فعالیت: 45 روز پیش
  4. مهم‌ترین رویداد اخیر: Answer (2 ماه پیش)

💡 پیشنهاد:
  - ارسال ایمیل بازگشت با پیشنهاد ویژه
  - دعوت به رویداد آنلاین
```

## ۶.۹ درس‌های آموخته‌شده

### ۶.۹.۱ درس‌های فنی

1. **ساده شروع کن:** Rule-based قبل از Deep Learning
2. **داده‌ی خوب > مدل پیچیده:** Feature Engineering اهمیت زیادی دارد
3. **Temporal Split اجباری:** هرگز Random Split در Time Series
4. **Persona-aware:** یک مدل برای همه کار نمی‌کند
5. **Interpretability لازم است:** حتی اگر مدل دقیق باشد

### ۶.۹.۲ درس‌های عملی

1. **مستندسازی از اول:** در انتها سخت‌تر است
2. **Version Control همه‌چیز:** کد، داده، مدل
3. **Reproducibility:** Random Seed ثابت
4. **Early Stopping:** از Overfitting جلوگیری
5. **Multiple Metrics:** فقط F1 کافی نیست

> **💡 مثال مفهومی:**
> 
> ساختن سیستم Churn Prediction برای SO مثل ساختن یک سیستم Moderation است:
> - **Rule-based:** مثل قانون «اگر Rep < 10 و ۳ Flag خورده → بررسی کن» — ساده و ضروری
> - **Feature Engineering:** مثل تعریف «Spam Score» و «Quality Score» — کار اصلی
> - **LSTM:** مثل سیستم تشخیص خودکار Troll — پیشرفته، اما بدون قوانین پایه بی‌فایده است
> - **Documentation:** مثل مستندات SO برای Moderatorها — بدون آن، تعمیرات غیرممکن است

```python
# تمام Pipeline در یک تابع
def predict_churn_for_user(
    eventlog: pl.DataFrame,
    user_id: int,
    cutoff: datetime,
    models: dict,
    use_ensemble: bool = True,
) -> dict:
    """
    پیش‌بینی Churn برای یک کاربر با توضیحات
    """
    # Rule-based
    wa = compute_wa(eventlog, user_id, cutoff, models['Tp'])
    p_rule = 1.0 if wa < models['Ap'] else 0.0
    
    # Enhanced WA
    wa_recency = compute_wa_recency(eventlog, user_id, cutoff)
    p_wa = sigmoid(models['wa_threshold'] - wa_recency)
    
    # LSTM
    sequence = create_sequence(eventlog, user_id, cutoff)
    with torch.no_grad():
        p_lstm = models['lstm'].predict_proba(sequence)[0, 1].item()
    
    # Ensemble
    if use_ensemble:
        p_final = weighted_ensemble(p_rule, p_wa, p_lstm, models['weights'])
    else:
        p_final = p_lstm
    
    # Generate explanation
    explanation = generate_explanation(
        user_id,
        {'rule': p_rule, 'wa': p_wa, 'lstm': p_lstm, 'final': p_final},
        {'wa': wa, 'wa_recency': wa_recency, 'ap': models['Ap']},
    )
    
    return {
        "user_id": user_id,
        "churn_probability": p_final,
        "prediction": "Churn" if p_final > 0.5 else "Active",
        "confidence": max(p_final, 1 - p_final),
        "explanation": explanation,
        "components": {
            "rule_based": p_rule,
            "enhanced_wa": p_wa,
            "lstm": p_lstm,
        }
    }
```
